# Engine

Native C side of Menhir games.

| Folder              | What                                                                    |
|---------------------|-------------------------------------------------------------------------|
| `Player/`           | The game player: window, data loading and the rendering pipeline (see below) |
| `Runtime/`          | Runtime for C code generated by IL2C (`Translator/`): objects, arrays, strings, casts, .NET arithmetic, internal calls |
| `ThirdParty/bdwgc/` | Boehm-Demers-Weiser garbage collector 8.2.8, vendored (MIT-style license, see `LICENSE.txt`) |
| `ThirdParty/glfw/`  | GLFW 3.4, vendored (zlib license, see `LICENSE.md`): windows, OpenGL context, input |
| `ThirdParty/glad/`  | OpenGL 3.3 Core loader generated by glad 2 (see its `README.md`) |

The header `Runtime/include/menhir/runtime.h` documents the object model.

## Player

**File → Build** in the editor (Ctrl+B; **Build And Run**: Ctrl+Shift+B) writes `Build/<Name>/` in the
project (git-ignored):

- `main.c`: one standalone C file. It is `Player/src/main.c` with every file it includes pasted in,
  glad's loader, and the editor's shaders as C strings. It opens the window with GLFW, sets up OpenGL
  and renders like the editor's viewport: shadow maps, procedural sky, lit meshes in HDR and the whole
  post-processing stack.
- `GameData.binchunk`: the game's data in binary chunks (settings, scenes, meshes, textures), read when
  needed. The format is in [Docs/BinChunk.md](../Docs/BinChunk.md).
- The executable, compiled from `main.c` against GLFW (compiled once into the project's `Cache/Player/`).

The build includes the scenes ticked in **Project Settings → Build** (all of them when none is, the open
one first), with the open scene's unsaved changes. The game renders from the scene's first **Camera**
(or from (0, 1, 10) looking down -Z), at the window size of the build settings. **Esc** quits.

```sh
./MyGame [--scene n] [--size 1280x720] [--frames n] [--screenshot out.ppm] [--data GameData.binchunk] [--dump]
```

`--dump` prints the first frame's matrices, lights and shadow maps without opening a window; the editor's
tests compile the player with `-DMENHIR_HEADLESS` and compare it with what the editor computes.

Building needs GCC or Clang (set in **Project Settings → Build**). On Linux, GLFW uses X11 and needs its
development headers to compile (Debian/Ubuntu: `libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev
libxi-dev libxext-dev`); the game loads the X11 libraries when it starts. Windows (MinGW) and macOS follow GLFW's
build files but have not been tried yet.

| File | What |
|------|------|
| `src/main.c` | Options, GLFW window, main loop |
| `src/mh_math.h` | Vectors and matrices with System.Numerics' conventions |
| `src/mh_data.h`, `mh_data.c` | The binchunk reader |
| `src/mh_scene.c` | World matrices, lights and camera (`Scene`, `SceneEnvironment`) |
| `src/mh_shadows.c` | Shadow map placement (`ShadowSetup`) |
| `src/mh_gl.c`, `mh_renderer.c`, `mh_post.c` | OpenGL helpers, scene passes, post-processing (`GLRenderer`, `GLPostProcessor`) |
| `src/mh_dump.c` | `--dump` |

Not there yet: scripts (IL2C), input for games, scene changes at run time, audio, imported meshes.
